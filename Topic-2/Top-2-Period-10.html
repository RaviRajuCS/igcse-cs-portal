My teaching route
Lesson overview

Period 10 · Choosing an Error Detection Method

Topic 2 · Data Transmission: Students consolidate parity checks, checksums and echo checks, then choose an appropriate method for different situations.

Success criteria: Students can describe the three methods, compare their operation and limitations, and justify a suitable error-detection method for a scenario.

Prior learning: Periods 6–9 — transmission errors, parity, checksum and echo check.

Key vocabulary: parity check, checksum, echo check, error detection, comparison, suitability, limitation, scenario.

My teaching route

From remembering to choosing

  1. Rapid retrieval of the three methods.
  2. Build a one-page comparison.
  3. Use short scenarios to select a method.
  4. Require a reason, not just a method name.
  5. Address common exam traps.
  6. Finish with a mixed Cambridge-style assessment.
Teaching principle: “Suitable” questions require a method + reason. Students must link the method's operation to the scenario.
0–7 min · Retrieval

Three methods in three phrases

ParityCount the 1s.
ChecksumCalculate a checking value.
Echo checkReturn and compare.
Challenge: Explain each phrase in a complete sentence.
7–15 min · Compare

The complete comparison

MethodHow it worksMain limitation
Parity checkUses a parity bit and checks the number of 1s.Some multiple-bit errors can remain undetected.
ChecksumCalculates a value from the data and compares it at the receiver.A matching value does not guarantee every possible error is detected.
Echo checkSends received data back for comparison with the original.Requires additional transmission and communication resources.
15–24 min · Scenario practice

Choose and justify

Scenario A: A simple system needs a basic check of a small group of binary bits.

Suggested: Parity check — it is simple and checks the number of 1s.

Scenario B: A system wants to calculate a checking value from a group of data.

Suggested: Checksum — a value can be calculated and compared at the receiver.

Scenario C: A system can return the received data and directly compare it with the original.

Suggested: Echo check — the received data is returned for direct comparison.
24–33 min · Interactive

Method selector

1. A binary transmission system wants a simple check based on the number of 1s.

2. A system needs to compare a calculated value at the receiving end.

3. The receiver can send the received data back to the sender.

33–39 min · Exam technique

How to justify a choice

Weak: “Use a checksum.”
Strong: “Use a checksum because the system can calculate a value from the data and compare it with the checksum received.”

A good justification contains:

  1. The chosen method.
  2. How that method works.
  3. Why that feature suits the scenario.
39–44 min · Assessment

Mixed Cambridge-style questions

  1. State the purpose of error detection.
  2. Explain how a parity check works.
  3. Explain how a checksum detects an error.
  4. Describe how an echo check works.
  5. State one limitation of parity checking.
  6. State one limitation of an echo check.
  7. Choose a suitable method for a scenario and justify your choice.
Marking focus: Method names alone are not enough when the question asks you to explain or justify.
44–48 min · Mastery challenge

One scenario — three answers

A company sends important data between two computers. The system designer is considering parity, checksum and echo checking.

Ask students to identify one strength and one limitation of each method, then recommend one.

Parity is simple but cannot detect every possible error. A checksum checks a calculated value but is not a guarantee against every possible error. An echo check allows direct comparison but requires additional transmission. The best choice depends on the system's requirements and constraints.

1 · The three methods

Parity checkAdd a parity bit and check the number of 1s.
ChecksumCalculate a value and compare it at the receiver.
Echo checkSend received data back and compare it with the original.

2 · Quick comparison

QuestionAnswer
Which one counts 1s?Parity
Which one calculates a value?Checksum
Which one returns data?Echo check
Which needs extra return transmission?Echo check

3 · Interactive method selector

Which method? The system adds one bit so the number of 1s can be checked.

Which method? The receiver sends the data it received back to the sender.

4 · Scenario challenge

A small binary system needs a simple method that checks whether the number of 1s follows an agreed rule.

The receiver can return the received data to the sender for comparison.

5 · Learn to justify

When an exam asks “Which method would be suitable and why?”, use this structure:

Choose → Describe → Link
Choose the method → describe how it works → link that feature to the scenario.

Example: “Use an echo check because the received data can be sent back to the sender for direct comparison with the original.”

6 · Strengths and limitations

MethodStrengthLimitation
ParitySimple check.Some errors can go undetected.
ChecksumChecks a group of data using a calculated value.Not a guarantee that every error is detected.
EchoDirect comparison with original.Needs extra transmission.

7 · Exam practice

Question: A system can send received data back to the sender. Which error-detection method would use this feature? Explain your answer.

An echo check. The receiver sends the data it received back to the sender, and the sender compares it with the original data. A difference indicates that an error has occurred.

9 · Common exam mistakes

  • Choosing a method without giving a reason.
  • Confusing checksum with parity.
  • Forgetting that echo check sends data back.
  • Claiming any one method detects every possible error.
  • Giving vague statements such as “it is better” without linking the reason to the scenario.
