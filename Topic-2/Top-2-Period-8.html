Lesson overview

Period 8 · Checksum

Topic 2 · Data Transmission: Students learn how a checksum can be calculated from transmitted data and then compared at the receiving end to detect errors.

Success criteria: Students can explain the purpose of a checksum, calculate a simple checksum from data blocks, compare sender and receiver values, and explain what a mismatch means.

Prior learning: Periods 6–7 — transmission errors and parity checking.

Key vocabulary: checksum, data block, calculated value, sender, receiver, compare, mismatch, error detection.

My teaching route

From data blocks to a checking value

  1. Retrieve the purpose of error detection.
  2. Contrast checksum with a parity bit.
  3. Split a small data set into blocks.
  4. Calculate a simple checksum.
  5. Transmit the data and checksum.
  6. Recalculate at the receiver and compare.
  7. Discuss what a match or mismatch tells us.
Teaching principle: The checksum is a value calculated from the data; the receiver recalculates it and compares the values.

What is a checksum?

A checksum is a value calculated from a block of data. The checksum is transmitted along with the data.

The receiver performs the same calculation using the received data. The newly calculated value is compared with the received checksum.

Core idea: Same checksum → data is likely unchanged. Different checksum → an error has been detected.

Parity check vs checksum

Adds a parity bit.Calculates a value from a block/group of data.

37–42 min · Critical thinking

Does a matching checksum prove perfection?

No. A checksum is an error-detection method, not a guarantee that every possible error has been detected.

Different data can sometimes produce the same checking value, depending on the checksum method. Therefore a matching checksum means the check has passed, not that errors are mathematically impossible.

8 · Exam practice

Question: Explain how a checksum can be used to detect an error in transmitted data.

The sender calculates a checksum from the data and sends it with the data. The receiver recalculates the checksum from the received data and compares it with the received checksum. If the values are different, an error has been detected.

9 · Important limitation

A checksum is an error-detection technique. It does not automatically correct the data, and a matching checksum does not guarantee that every possible error has been detected.

Exam wording: Say “an error is detected” rather than “the checksum fixes the error.”

10 · Common mistakes

  • Forgetting to recalculate the checksum at the receiver.
  • Comparing the wrong values.
  • Thinking a checksum automatically corrects the data.
  • Assuming every checksum algorithm is simple addition.
  • Claiming a matching checksum proves that no error is possible.
