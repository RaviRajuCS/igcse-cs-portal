Lesson overview

Period 7 · Parity Checks

Topic 2 · Data Transmission: Students learn how a parity bit can be added to transmitted data so that the receiver can detect certain errors.

Success criteria: Students can explain parity checking, distinguish even and odd parity, calculate the required parity bit, and explain what happens when a parity check fails.

Prior learning: Period 6 — transmission errors, including data loss, gain and change.

Key vocabulary: parity bit, parity check, even parity, odd parity, error detection, number of 1s, error detected.

My teaching route

Make the extra bit meaningful

  1. Retrieve the three types of transmission error.
  2. Show a binary data word and count its 1s.
  3. Introduce the extra parity bit.
  4. Build even parity first, step by step.
  5. Repeat with odd parity.
  6. Show how a changed bit can make the parity rule fail.
  7. Finish with the limitation: some errors can pass the parity check.
Memory rule: Parity checking adds one extra bit so the number of 1s can be checked.

What is a parity bit?

A parity bit is an extra bit added to a group of data bits. It is used to make the total number of 1s either even or odd, depending on the parity system being used.

15–25 min · Guided example

Even parity — step by step

Suppose the data is 1011001.

Step 1: Count the 1s.

1011001 contains 4 ones.

Step 2: Even parity requires the total number of 1s to remain even.

There are already 4 ones, so the parity bit is 0.

Result: 10110010 if the parity bit is placed at the end.

25–32 min · Guided example

Odd parity — step by step

Use the same data: 1011001.

There are 4 ones. Odd parity requires the total number of 1s to be odd.

We need one more 1, so the parity bit is 1.

Result: 10110011 if the parity bit is placed at the end.

Notice: The same data can have different parity bits depending on whether even or odd parity is being used.

38–43 min · Critical thinking

What is the limitation?

Parity checking does not detect every possible error.

If two bits change, the number of 1s may still have the correct parity. The receiver could therefore accept the data even though it is incorrect.

Exam point: A parity check can detect many single-bit errors, but it cannot detect all errors.

1 · What is a parity bit?

A parity bit is an extra bit added to transmitted data for error checking.

The parity bit is selected so that the total number of 1s follows the agreed rule: even or odd.

2 · Even parity

With even parity, the total number of 1s, including the parity bit, must be even.

Example: 1011001 has four 1s.

Four is already even → parity bit = 0.

Result: 10110010

3 · Odd parity

With odd parity, the total number of 1s, including the parity bit, must be odd.

Example: 1011001 has four 1s.

Four is even, so add one more 1 → parity bit = 1.

Result: 10110011

5 · How does the receiver detect an error?

The receiver counts the number of 1s in the received sequence and checks whether it matches the agreed parity rule.

Expected even parity: an odd total means the parity check has failed → an error has been detected.

The check detects an error; it does not automatically repair the incorrect bit.

6 · One-bit error

Suppose a sequence using even parity originally contains an even number of 1s. If one bit changes from 0 to 1 or from 1 to 0, the parity changes.

Result: the receiver can detect that an error has occurred.

7 · Limitation

Suppose two bits change. The number of 1s can change by two, leaving the parity even when even parity is expected.

Therefore: parity checking cannot detect every possible transmission error.
With even parity, a valid sequence might have an even number of 1s. If two bits change, the number of 1s may remain even, so the parity check can still pass even though the data is wrong.

8 · Exam practice

Question: Explain how a parity check can detect an error in transmitted data.

A parity bit is added so that the total number of 1s is even or odd according to the agreed rule. The receiver counts the 1s and checks the rule. If the expected parity is not achieved, an error is detected.

9 · Common mistakes

  • Forgetting to include the parity bit when checking the total number of 1s.
  • Confusing even parity with an even number of data bits.
  • Thinking parity automatically corrects the error.
  • Claiming parity detects every possible error.
  • Failing to count the 1s before choosing the parity bit.
