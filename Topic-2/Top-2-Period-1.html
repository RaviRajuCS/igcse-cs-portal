Lesson overview

Period 1 · Data Packets

Topic 2 · Data Transmission: We begin the new topic by understanding why data sent over a network is divided into packets and what information is carried in each packet.

Success criteria: Students can explain why data is split into packets, identify the header, payload and trailer, describe the purpose of important header fields, and explain why packet sequence numbers are needed.

Prior learning: Topic 1 — binary data, storage and compression.

Key vocabulary: packet, packet header, payload, trailer, IP address, sequence number, packet size, error checking, packet reassembly.

My teaching route

Start with a real-life analogy

Ask students to imagine sending a huge book through a postal service. Instead of sending one enormous package, the book can be divided into smaller numbered packages.

  1. Split the message.
  2. Put each part into a packet.
  3. Address each packet.
  4. Send the packets.
  5. Reassemble them at the destination.
Core idea: packets make large amounts of data easier to control and transmit across networks.
0–5 min · Hook

Would you send this as one piece?

Suppose you need to send a very large video across a network. Ask:

  • What happens if the route becomes busy?
  • What happens if part of the transmission is corrupted?
  • Would it be sensible to send everything as one continuous stream?
Transition: Networks can divide large messages into smaller packets.
5–13 min · Teach

What is a data packet?

A data packet is a small part of a message or data that is transmitted over a network. After transmission, the packets are reassembled to form the original message.

Each packet carries part of the original data plus information needed to help it reach its destination and be handled correctly.

13–22 min · Packet structure

Header · Payload · Trailer

PartPurpose
HeaderInformation about the packet, including source/destination IP addresses and sequence information.
PayloadThe actual data being carried.
TrailerInformation identifying the end of the packet and providing error checking information.
Memory aid: Header = instructions about the packet · Payload = the data · Trailer = ending/check information.
22–30 min · Header fields

What is inside the header?

  • Source IP address — identifies the sending device.
  • Destination IP address — identifies the receiving device.
  • Sequence number — helps put packets back into the correct order.
  • Packet size — allows the receiving station to check packet size/integrity.
Exam point: sequence numbers are essential because packets may not arrive in their original order.

35–40 min · Reassembly

Why do packets need sequence numbers?

Imagine packets arrive as:

3
1
4
2

The receiving computer uses the sequence numbers to rearrange them:

1 → 2 → 3 → 4

This allows the original message to be reconstructed in the correct order.

40–45 min · Assessment

Cambridge-style questions

  1. Define a data packet.
  2. State the three main parts of a data packet.
  3. State two pieces of information found in a packet header.
  4. Explain why a sequence number is included in a packet header.
  5. State the purpose of the payload.
Marking focus: students should explain the reason for sequence numbers, not merely state that they “number packets”.
45–50 min · Exit ticket

Three things to remember

  1. A message can be divided into smaller packets.
  2. A packet contains a header, payload and trailer.
  3. Sequence numbers help packets be reassembled correctly.

8 · Exam practice

Question: Explain why a large message is divided into packets before transmission.

Dividing data into smaller packets makes it easier to control and transmit. Packets can travel through a network and can be reassembled at the destination to recreate the original message.

9 · Common mistakes

  • Calling the payload the whole packet.
  • Forgetting that the payload contains the actual data.
  • Thinking sequence numbers are addresses.
  • Forgetting that packets must be reassembled.
