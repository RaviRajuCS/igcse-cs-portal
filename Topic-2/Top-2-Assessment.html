Teacher Mark Scheme / Model Answers

  1. Q1: Data can be corrupted/changed during transmission and must be checked for errors. Examples include data being lost, gained or changed. Interference/noise can alter transmitted signals/bits.
  2. Q2: Parity checks detect certain transmission errors by checking the number of 1 bits. 2(b) = 1, because 1011010 contains five 1s and even parity requires six. Even parity gives an even total number of 1s; odd parity gives an odd total. Receiver checks/recalculates parity; mismatch indicates an error.
  3. Q3: Checksum: sender calculates a value from the data and transmits it; receiver recalculates the value and compares it with the received checksum; mismatch indicates an error. Echo: receiver sends the received data back to the sender; sender compares it with the original; mismatch indicates an error.
  4. Q4: Check digit detects errors in data entry. It is calculated from the other digits; when entered, it is recalculated and compared; mismatch flags an error. Examples: ISBN and bar codes.
  5. Q5: Positive acknowledgement/ACK means data was received without a detected error. Negative acknowledgement/NACK means an error was detected. Timeout is the waiting period before the sender decides that the expected response has not arrived. Error path: receiver detects error → sends NACK → sender resends.
  6. Q6: Encryption protects confidentiality by transforming readable data into ciphertext so unauthorised people cannot readily understand intercepted information. Readable original = plaintext; encrypted form = ciphertext.
  7. Q7: Symmetric encryption uses the same shared secret key for encryption and decryption. A key-management problem is securely sharing/distributing the secret key to the other party.
  8. Q8: Public key and private key. For confidentiality: sender obtains recipient's public key → encrypts plaintext → ciphertext is sent → recipient uses corresponding private key to decrypt.
  9. Q9: ARQ; NACK; recipient's public key; recipient's private key.
  10. Q10: Symmetric uses one shared secret key; asymmetric uses a public/private key pair. The sender can use the recipient's public key to encrypt, while the recipient keeps the private key secret and uses it for the corresponding decryption operation.
