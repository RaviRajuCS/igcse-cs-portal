Lesson overview

Period 14 · Automatic Repeat Request (ARQ)

Topic 2 · Data Transmission: Students learn how Automatic Repeat Request (ARQ) establishes that data has been received without error by using acknowledgements, negative acknowledgements and a timeout.

Success criteria: Students can describe the ARQ sequence, distinguish a positive acknowledgement from a negative acknowledgement, explain the purpose of a timeout, and trace when data is resent.

Prior learning: Periods 6–10 — parity, checksum, echo check and other error-detection methods.

Key vocabulary: ARQ, positive acknowledgement (ACK), negative acknowledgement (NACK), timeout, resend, sender, receiver.

My teaching route

Make the conversation between sender and receiver visible

  1. Retrieve why error detection is needed.
  2. Introduce ARQ as a method that combines error detection with feedback.
  3. Trace a successful transmission and positive acknowledgement.
  4. Trace an error and negative acknowledgement.
  5. Introduce timeout when no response arrives.
  6. Show automatic retransmission.
  7. Practise identifying the exact event that triggers a resend.
Memory rule: Send → check → ACK / NACK → timeout if no response → resend.

32–39 min · Timeout

What if no acknowledgement arrives?

Sometimes the sender receives neither an ACK nor a NACK. The response itself may have been lost or delayed.

A timeout is the agreed period the sender waits for the expected response. If it expires, the sender can automatically resend the data.

Important: Timeout prevents the sender from waiting forever.

ARQ adds feedback to the error-detection process.

2 · Positive acknowledgement (ACK)

If the receiver checks the data and finds no error, it sends an ACK.

ACK means: “The data was received correctly.”

The sender can then continue rather than unnecessarily resending the data.

3 · Negative acknowledgement (NACK)

If the receiver detects an error, it sends a NACK.

NACK means: “There is a problem with the data; send it again.”

4 · Timeout

What happens if the ACK or NACK never reaches the sender?

The sender waits for a predetermined period. If that period expires without the expected response, a timeout occurs.

The sender then resends the data.

5 · Interactive ARQ check

The receiver finds no error and sends a response. Which response?

The receiver detects an error. Which response?

The sender receives no response before the agreed waiting period ends. What occurs?

6 · Trace a successful transmission

  1. Sender transmits the data.
  2. Receiver receives and checks it.
  3. No error is detected.
  4. Receiver sends ACK.
  5. Sender receives ACK.
  6. Transmission can continue.

7 · Trace an error

  1. Sender transmits the data.
  2. Receiver detects an error.
  3. Receiver sends NACK.
  4. Sender receives NACK.
  5. Sender resends the data.

8 · Trace a lost response

  1. Sender transmits the data.
  2. Receiver receives it correctly.
  3. The expected acknowledgement does not reach the sender.
  4. The waiting period expires.
  5. Timeout occurs.
  6. Sender automatically resends.
Why? The sender cannot assume that the transmission process completed successfully without the expected response.

10 · Exam practice

Question: Explain how ARQ can establish that data has been received without error.

The receiver checks the transmitted data. If no error is detected, it sends a positive acknowledgement to the sender. If an error is detected, it sends a negative acknowledgement and the sender resends the data. If no acknowledgement is received before the timeout, the sender resends the data.

11 · Challenge

Why is a timeout useful even when the receiver has not detected an error?

The acknowledgement may have been lost or delayed. The timeout prevents the sender from waiting indefinitely and allows it to resend the data when no expected response arrives.

12 · Common mistakes

  • Confusing ACK with NACK.
  • Thinking timeout means the data definitely contained an error.
  • Forgetting that a timeout can occur because the response was lost or delayed.
  • Forgetting that NACK causes a resend.
  • Forgetting that ARQ requires feedback from the receiver.
