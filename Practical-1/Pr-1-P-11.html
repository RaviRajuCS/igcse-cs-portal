Breaking a Problem into Subroutines

Students now begin to organise larger algorithms into smaller, reusable sections called subroutines. This helps them design, test and debug complex programs systematically.

Core idea: A large problem becomes easier when repeated or logically separate tasks are placed into named procedures or functions.

1 · Why modularise?

Imagine a program that repeatedly needs to display the same menu. Should the menu instructions be copied into five different places?
No. Put the menu in a named subroutine and call it whenever it is needed. This reduces duplication and makes maintenance easier.
8–18 min · Teach

2 · A simple PROCEDURE

PROCEDURE DisplayWelcome()
  OUTPUT "Welcome to the system"
ENDPROCEDURE

CALL DisplayWelcome()

A procedure is a named block of instructions that can be called when required.

18–27 min · Teach

3 · Procedure with a parameter

PROCEDURE DisplayDouble(Number)
  OUTPUT Number × 2
ENDPROCEDURE

CALL DisplayDouble(7)

A parameter allows information to be passed into a subroutine. Here, Number receives the value 7.

27–35 min · Worked example

4 · Example #1 — Grade message

PROCEDURE ShowGrade(Grade)
  IF Grade >= 70 THEN
    OUTPUT "Excellent"
  ELSE
    OUTPUT "Keep practising"
  ENDIF
ENDPROCEDURE

CALL ShowGrade(82)

5 · Example #2 — Reusable validation

PROCEDURE CheckMark(Mark)
  IF Mark >= 0 AND Mark <= 100 THEN
    OUTPUT "Valid"
  ELSE
    OUTPUT "Invalid"
  ENDIF
ENDPROCEDURE
The same validation logic can be called whenever a mark needs checking.

6 · Workout — Positive/negative checker

Create a procedure CheckNumber(Number) that displays “Positive”, “Negative” or “Zero”.
PROCEDURE CheckNumber(Number)
  IF Number > 0 THEN
    OUTPUT "Positive"
  ELSE IF Number < 0 THEN
    OUTPUT "Negative"
  ELSE
    OUTPUT "Zero"
  ENDIF
ENDPROCEDURE

8 · Workout — Array helper

Write a procedure DisplayArray that receives an array and displays its five elements.
PROCEDURE DisplayArray(A)
  FOR I ← 1 TO 5
    OUTPUT A[I]
  NEXT I
ENDPROCEDURE

When teaching exact Cambridge pseudocode syntax, use the array-parameter convention specified for the course.

9 · Debugging workout

PROCEDURE DisplayDouble(Number)
  OUTPUT Number × 2
ENDPROCEDURE

CALL DisplayDouble()

What is missing from the call?

The procedure expects a value for Number. A suitable call is, for example, CALL DisplayDouble(8).

13 · Common mistakes

  • Defining a procedure but never calling it.
  • Forgetting required parameters in a call.
  • Using the wrong parameter order.
  • Duplicating a subroutine's code instead of reusing it.
  • Making a subroutine responsible for too many unrelated tasks.

14 · Self-assessment
