Integrated Problem Solving

Students now combine the practical techniques learned so far into complete solutions. The emphasis is on designing an algorithm from a problem statement, selecting suitable structures and testing the finished solution.

Core idea: Do not choose a technique first. Understand the problem, identify the required data and operations, then choose the most suitable combination of arrays, loops, selection, subroutines, validation, files and search/sort.

0–8 min · Retrieval

1 · Choose the right tool

A system must store 20 marks, find the highest mark and later display all marks in ascending order. Which techniques are likely to be useful?
An array can store the marks; iteration can process them; an extreme-value algorithm can find the highest; and a sorting algorithm can arrange them.
8–18 min · Teach

2 · Read the problem before coding

  1. Identify inputs.
  2. Identify required outputs.
  3. Identify constraints and validation rules.
  4. Identify data structures.
  5. Break repeated tasks into subroutines where useful.
  6. Plan testing before declaring the solution complete.
Teacher habit: Ask students to underline the verbs in a question: input, store, calculate, search, sort, count, validate, display.
18–27 min · Worked example

3 · Example #1 — Student marks

Task: Input 8 marks, validate each mark from 0–100, calculate the average, find the highest mark and display the marks in ascending order.

1. Validate and store 8 marks in A
2. Total ← 0; Highest ← A[1]
3. Traverse A to calculate Total and Highest
4. Average ← Total ÷ 8
5. Bubble sort A in ascending order
6. Output Average, Highest and sorted A
27–35 min · Worked example

4 · Example #2 — File + search

Task: Read 15 student IDs from a file, input a target ID and report whether it occurs.

Found ← FALSE
OPENFILE "IDs.txt" FOR READ
FOR I ← 1 TO 15
  READFILE "IDs.txt", ID
  IF ID = Target THEN
    Found ← TRUE
  ENDIF
NEXT I
CLOSEFILE
This is a good example of combining file handling + iteration + linear search + Boolean state.
35–42 min · Worked example

5 · Example #3 — Subroutine design

A large program repeatedly needs to validate marks. Separate that responsibility from the main algorithm.

PROCEDURE GetValidMark()
  REPEAT
    INPUT Mark
  UNTIL Mark >= 0 AND Mark <= 100
ENDPROCEDURE

Then the main algorithm can focus on what to do after a valid mark is available.

42–47 min · Guided workout

6 · Plan before coding

Design the stages for a program that stores 10 prices, validates each price as positive, finds the cheapest price and displays the prices in ascending order.
  1. Repeatedly input each price until it is positive.
  2. Store valid prices in an array.
  3. Find the minimum using a traversal.
  4. Sort the array into ascending order.
  5. Display the minimum and sorted array.
47–50 min · Exit

2 · Worked Example #1 — Complete mark processor

FOR I ← 1 TO 8
  REPEAT
    INPUT A[I]
  UNTIL A[I] >= 0 AND A[I] <= 100
NEXT I

Total ← 0
Highest ← A[1]
FOR I ← 1 TO 8
  Total ← Total + A[I]
  IF A[I] > Highest THEN
    Highest ← A[I]
  ENDIF
NEXT I
Average ← Total ÷ 8

Create a function IsValidMark(Mark) that returns TRUE when Mark is from 0 to 100 inclusive.

ENDFUNCTION

7 · Worked Example #3 — Integrated sorting

FOR Pass ← 1 TO 5
  FOR I ← 1 TO 6 - Pass
    IF A[I] > A[I + 1] THEN
      Temp ← A[I]
      A[I] ← A[I + 1]
      A[I + 1] ← Temp
    ENDIF
  NEXT I
NEXT Pass

Before using a sort, students should confirm that sorting is actually required by the problem.

8 · Debugging workout

Total ← 0
FOR I ← 1 TO 10
  INPUT A[I]
NEXT I
Average ← Total ÷ 10

What important processing step is missing?

The algorithm never adds the array values to Total. It needs a traversal containing Total ← Total + A[I] before calculating Average.

10 · Challenge — Complete mini system

Design an algorithm for 10 student marks that: validates input, stores the marks, calculates the average, counts passes (≥50), finds the highest mark and displays the sorted marks.
  1. Validate and store 10 marks.
  2. Traverse to calculate Total, CountPass and Highest.
  3. Calculate Average.
  4. Bubble sort the array ascending.
  5. Output Average, CountPass, Highest and the sorted array.
  6. Test normal, boundary and invalid input.

11 · Think like an examiner

12 · Mini exam challenge

A file contains 20 marks. Read the marks, count how many are at least 50, find the highest mark and output the results. State the main algorithmic components you would use.

File handling to read the records; iteration to process all 20 marks; a counter to count passes; an extreme-value pattern to find the highest; and output statements to report the results.

13 · Common mistakes

  • Coding before understanding every requirement.
  • Choosing an algorithm that does not match the task.
  • Forgetting to initialise counters, totals or flags.
  • Mixing input, processing and output so heavily that errors become difficult to find.
  • Testing only the happy path.
  • Ignoring constraints stated in the question.

14 · Self-assessment
