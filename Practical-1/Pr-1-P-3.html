Making Decisions in Algorithms

Students now move beyond simple sequence. A useful algorithm often needs to make a decision based on a condition. This period introduces selection using IF, THEN, ELSE, with many progressively harder workouts.

Core idea: Sequence follows every step. Selection chooses between different paths depending on whether a condition is TRUE or FALSE.

1 · Why do we need selection?

A program receives a student's mark. If the mark is 50 or more, it should display “Pass”; otherwise it should display “Fail”.

Ask: can one fixed sequence produce both outputs for every possible mark?

No. The program needs a condition to choose the appropriate path.
8–18 min · Teach

2 · The basic IF structure

IF Mark >= 50 THEN
  OUTPUT "Pass"
ELSE
  OUTPUT "Fail"
ENDIF

The condition Mark >= 50 is tested. Exactly one branch is selected.

TRUEMark is 50 or more → Pass.
FALSEMark is below 50 → Fail.

3 · Example #1 — Positive or negative

Problem: Input a number. Display “Positive” if it is greater than zero; otherwise display “Not positive”.
INPUT Number
IF Number > 0 THEN
  OUTPUT "Positive"
ELSE
  OUTPUT "Not positive"
ENDIF

Test with 8, −3 and 0.

4 · Example #2 — Larger of two numbers

Problem: Input A and B. Display the larger value.
INPUT A
INPUT B
IF A > B THEN
  OUTPUT A
ELSE
  OUTPUT B
ENDIF
Teacher discussion: What happens when A = B? This simple example is useful for introducing boundary and equality cases.

6 · Classroom challenge — Discount

Problem: If the purchase total is $100 or more, give a 10% discount. Otherwise give no discount. Display the final price.

Students identify the condition and write the algorithm.

INPUT Total
IF Total >= 100 THEN
  Final ← Total × 0.90
ELSE
  Final ← Total
ENDIF
OUTPUT Final

6 · Workout — Largest of three

Input A, B and C. Display the largest value.

Try designing the algorithm before revealing the solution.

INPUT A
INPUT B
INPUT C
Largest ← A
IF B > Largest THEN
  Largest ← B
ENDIF
IF C > Largest THEN
  Largest ← C
ENDIF
OUTPUT Largest

This solution demonstrates that selection can update a stored best value.

11 · Challenge — Electricity tariff

Input units. If units are 100 or less, cost = units × 0.20. Otherwise cost = 20 + (units − 100) × 0.30. Display cost.
INPUT Units
IF Units <= 100 THEN
  Cost ← Units × 0.20
ELSE

ENDIF
OUTPUT Cost

12 · Debug this algorithm

INPUT Age
IF Age > 18 THEN
  OUTPUT "Adult"
ELSE
  OUTPUT "Child"
ENDIF

The requirement is: 18 or older = Adult. Find the error.

The condition should be Age >= 18, not Age > 18. The boundary value 18 would otherwise be incorrectly classified.

13 · Mini exam question

Write an algorithm that inputs a mark and outputs “Distinction” if the mark is 75 or more, otherwise outputs “Not distinction”.

INPUT Mark
IF Mark >= 75 THEN
  OUTPUT "Distinction"
ELSE
  OUTPUT "Not distinction"
ENDIF

14 · Common mistakes

  • Using > when the requirement says >=.
  • Forgetting ELSE when two outcomes are required.
  • Testing only ordinary values and ignoring boundaries.
  • Writing conditions that overlap incorrectly.
  • Failing to initialise a variable in a more advanced selection algorithm.
