Advanced String Validation

Students build on Period 27 by using strings for realistic validation tasks. They combine length checks, character checks, counters and Boolean flags to validate usernames, passwords and simple identifiers.

Core idea: Real-world string validation often involves several rules. Check each required rule and only accept the input when all required conditions are satisfied.

0–8 min · Retrieval

1 · One rule versus several rules

A password must be at least 8 characters long and contain at least one digit. Is checking its length alone enough?
No. Both requirements must be checked. A password can have eight characters and still contain no digit.
8–18 min · Teach

2 · Using flags for multiple requirements

HasDigit ← FALSE
FOR I ← 1 TO LENGTH(Password)
  IF Password[I] >= "0" AND Password[I] <= "9" THEN
    HasDigit ← TRUE
  ENDIF
NEXT I

The flag records whether at least one digit has been found.

18–27 min · Teach

3 · Combining validation rules

Valid ← TRUE
IF LENGTH(Password) < 8 THEN
  Valid ← FALSE
ENDIF

IF HasDigit = FALSE THEN
  Valid ← FALSE
ENDIF

IF Valid THEN
  OUTPUT "Accepted"
ELSE
  OUTPUT "Rejected"
ENDIF
Using one overall Valid flag keeps the final decision simple while each rule can be checked separately.
27–35 min · Worked example

4 · Example #1 — Username validation

INPUT Username
WHILE LENGTH(Username) < 5 OR LENGTH(Username) > 12 DO
  OUTPUT "Username must be 5 to 12 characters"
  INPUT Username
ENDWHILE
OUTPUT "Username accepted"

This is a clean single-rule validation. More rules can be added when the specification requires them.

35–42 min · Worked example

5 · Example #2 — Password requirements

Valid ← TRUE
HasDigit ← FALSE

IF LENGTH(Password) < 8 OR HasDigit = FALSE THEN

OUTPUT Valid

4 · Interactive check

5 · Worked Example #2 — Require two character types

HasDigit ← FALSE
HasA ← FALSE
FOR I ← 1 TO LENGTH(Text)
  IF Text[I] >= "0" AND Text[I] <= "9" THEN
    HasDigit ← TRUE
  ENDIF
  IF Text[I] = "A" THEN
    HasA ← TRUE
  ENDIF
NEXT I

IF HasDigit AND HasA THEN
  OUTPUT "Accepted"
ELSE
  OUTPUT "Rejected"
ENDIF

6 · Workout — Password test data

For the rule "at least 8 characters and at least one digit", provide one valid password and two invalid examples that fail different rules.
Valid: Computer7. Invalid for length: Comp7. Invalid for digit requirement: Computer.

7 · Worked Example #3 — Validation loop

INPUT Password
HasDigit ← FALSE
FOR I ← 1 TO LENGTH(Password)
  IF Password[I] >= "0" AND Password[I] <= "9" THEN
    HasDigit ← TRUE
  ENDIF
NEXT I

WHILE LENGTH(Password) < 8 OR HasDigit = FALSE DO
  OUTPUT "Password does not meet the requirements"
  INPUT Password
  HasDigit ← FALSE
  FOR I ← 1 TO LENGTH(Password)
    IF Password[I] >= "0" AND Password[I] <= "9" THEN
      HasDigit ← TRUE
    ENDIF
  NEXT I
ENDWHILE
OUTPUT "Accepted"

When a new password is entered, the flag must be reset and recalculated.

8 · Debugging workout

HasDigit ← FALSE
FOR I ← 1 TO LENGTH(Password)
  IF Password[I] >= "0" AND Password[I] <= "9" THEN
    HasDigit ← TRUE
  ELSE
    HasDigit ← FALSE
  ENDIF
NEXT I

Why can this fail even when the password contains a digit?

A later non-digit character can reset HasDigit to FALSE. Once a required digit has been found, the flag should remain TRUE.

14 · Final practical challenge

Create a password checker with three rules: minimum length 8, at least one digit and at least one "A". Test at least one valid password and three invalid passwords, each targeting a different failure.
  1. Input password.
  2. Check length.
  3. Traverse characters for a digit.
  4. Traverse characters for A.
  5. Combine the rules.
  6. Repeat until valid if required.
  7. Record expected results for each test.

15 · Common mistakes

  • Checking only one of several required rules.
  • Resetting a TRUE flag when a later character does not match.
  • Forgetting to reset a flag before checking a new input.
  • Using an inclusive rule when the specification requires an exact length.
  • Testing only valid strings.
  • Not designing a test that isolates each failure condition.

16 · Self-assessment
