Validation and Robust Algorithms

Students now bring together iteration, selection, arrays, subroutines and functions to make algorithms reliable. A correct algorithm should not simply work with ideal input; it should handle invalid or unexpected input appropriately.

Core idea: Validate input before processing it, and use testing to prove that the algorithm behaves correctly at boundaries and invalid cases.

0–8 min · Retrieval

1 · What makes input valid?

A program asks for a mark from 0 to 100. Why should −5 and 127 be rejected before the mark is processed?
They are outside the permitted range. Validation prevents invalid data from entering the main processing stage.
8–18 min · Teach

2 · Range validation

REPEAT
  INPUT Mark
UNTIL Mark >= 0 AND Mark <= 100

This is a common validation pattern. The loop continues until the input satisfies both boundary conditions.

18–27 min · Teach

3 · Validation with a procedure

PROCEDURE GetValidMark()
  REPEAT
    INPUT Mark
  UNTIL Mark >= 0 AND Mark <= 100
ENDPROCEDURE

Reusable validation can be separated from the main algorithm. The exact procedure/function design should follow the pseudocode specification being taught.

27–35 min · Worked example

4 · Example #1 — Valid menu choice

REPEAT
  OUTPUT "1. Add"
  OUTPUT "2. Search"
  OUTPUT "3. Exit"
  INPUT Choice
UNTIL Choice >= 1 AND Choice <= 3
Boundary test: 1 and 3 should be accepted; 0 and 4 should be rejected.
35–42 min · Worked example

5 · Example #2 — Validation + processing

REPEAT
  INPUT Age
UNTIL Age >= 0 AND Age <= 120

IF Age >= 18 THEN
  OUTPUT "Adult"
ELSE
  OUTPUT "Under 18"
ENDIF

Notice the order: validate first, then process the valid value.

8 · Test-data workout

For a valid mark range of 0–100, classify these test values: −1, 0, 50, 100, 101.
Invalid: −1, 101.   Valid: 0, 50, 100. The boundary values 0 and 100 are especially important.

9 · Debugging workout

REPEAT
  INPUT Mark
UNTIL Mark > 0 OR Mark < 100

Why does this not correctly validate a mark from 0 to 100?

The condition uses OR, so almost every number will satisfy it. The required condition is Mark >= 0 AND Mark <= 100.

10 · Challenge — Valid positive even number

REPEAT

12 · Mini exam question

Write an algorithm that repeatedly inputs a mark until it is valid (0–100 inclusive), then outputs “Pass” if the mark is at least 50 and “Fail” otherwise.

REPEAT

UNTIL Mark >= 0 AND Mark <= 100

IF Mark >= 50 THEN
  OUTPUT "Pass"

  OUTPUT "Fail"
ENDIF

13 · Common mistakes

  • Using OR when AND is required for a range.
  • Rejecting valid boundary values.
  • Processing the value before validating it.
  • Testing only normal values and ignoring invalid values.
  • Creating a validation loop whose condition never becomes false.
