Handling Multiple Decisions

Students now extend simple selection into multiple-choice decisions. They learn how to select one outcome from several possible ranges, how to order conditions correctly, and how to avoid overlapping or unreachable branches.

Teaching goal: Move from “one condition, two outcomes” to structured multi-way selection. Students should be able to explain why the order of conditions matters.

1 · From two outcomes to many

A program classifies a mark as A, B, C or Fail. Ask students: “Can one simple IF/ELSE produce four different outputs?”
Not with only one binary decision. We need additional conditions, for example nested IF statements or an ELSE IF style structure.
8–18 min · Teach

2 · ELSE IF thinking

IF Mark >= 80 THEN
  OUTPUT "A"
ELSE IF Mark >= 70 THEN
  OUTPUT "B"
ELSE IF Mark >= 60 THEN
  OUTPUT "C"
ELSE
  OUTPUT "Fail"
ENDIF

Conditions are checked from top to bottom. Once one condition is true, its branch is selected.

Important: The order matters. Testing Mark >= 60 before Mark >= 80 would classify an 85 as C if the structure were not carefully designed.

4 · Example #2 — Shipping charge

Weight ≤ 2 kg: $5. Weight 2–5 kg: $8. Above 5 kg: $12.
INPUT Weight
IF Weight <= 2 THEN
  Charge ← 5
ELSE IF Weight <= 5 THEN
  Charge ← 8
ELSE
  Charge ← 12
ENDIF
OUTPUT Charge

Notice how the second condition does not need to say “Weight > 2” because reaching it already means the first condition was false.

35–42 min · Debugging

5 · Find the design error

IF Mark >= 60 THEN
  OUTPUT "C or above"
ELSE IF Mark >= 80 THEN
  OUTPUT "A"
ELSE
  OUTPUT "Fail"
ENDIF

Why can the A branch never be reached?

If Mark is 80, it is already >= 60, so the first branch runs. The ELSE IF is reached only when Mark is below 60, making Mark >= 80 impossible. Put the more restrictive/higher threshold first.

  Price ← 0
ELSE IF Age <= 15 THEN

ELSE IF Age <= 59 THEN

ELSE

47–50 min · Exit

7 · The three golden rules

  1. Put conditions in a logical order.
  2. Check the boundary values.
  3. Make sure every possible input has an outcome.

7 · Workout — Electricity tariff

Units 0–100 cost $0.20 each; 101–200 cost $20 plus $0.30 for each unit above 100; above 200 cost $50 plus $0.40 for each unit above 200.

Identify the three ranges and write the conditions.

IF Units <= 100 THEN
  Cost ← Units × 0.20
ELSE IF Units <= 200 THEN
  Cost ← 20 + (Units − 100) × 0.30
ELSE
  Cost ← 50 + (Units − 200) × 0.40
ENDIF

8 · Debugging workout

IF Score >= 50 THEN
  OUTPUT "Pass"
ELSE IF Score >= 80 THEN
  OUTPUT "Distinction"
ELSE
  OUTPUT "Fail"
ENDIF

Find the unreachable outcome.

“Distinction” is unreachable because every score >= 80 is already >= 50 and therefore takes the first branch. Put the >= 80 condition first.

Input BMI. Below 18.5 = Underweight; 18.5–24.9 = Healthy; 25–29.9 = Overweight; 30+ = Obese.

13 · Common mistakes

  • Putting a broad condition before a more specific condition.
  • Forgetting a final ELSE for valid inputs not covered earlier.
  • Incorrect boundary operators such as > instead of >=.
  • Assuming ranges without testing their boundaries.
  • Creating a branch that can never be reached.
