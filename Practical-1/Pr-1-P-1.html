From Problem to Solution

This practical studio begins Algorithm Design and Problem-solving. Students learn that successful programming starts before coding: first understand the problem, identify requirements, decompose it and describe the inputs, processes, outputs and storage involved.

0–8 min · Warm-up

1 · What exactly is the problem?

Suppose a school wants a program that calculates a student's final percentage from five test scores.

Before thinking about code, ask:
  1. What information will the program need?
  2. What calculation must it perform?
  3. What result should it produce?
  4. Does anything need to be stored?
Key habit: Never rush from a question straight into code. First identify what the problem is asking the computer to do.
8–18 min · Analysis

2 · IPO analysis

INPUTFive test scores.
PROCESSAdd the scores and calculate the percentage/average.
OUTPUTFinal percentage or average.
STORAGEScores may be stored in variables or an array.
Teacher prompt: Ask students to identify IPO before showing them any pseudocode.
18–28 min · Decomposition

3 · Break a problem into smaller parts

A large problem becomes easier when it is divided into manageable sub-problems.

STUDENT MARKS SYSTEM
→
INPUT MARKS
+
CALCULATE TOTAL
+
CALCULATE AVERAGE
+
DISPLAY RESULT

This is decomposition: breaking the problem into component parts that can be designed and solved separately.

28–36 min · Abstraction

4 · What should we ignore?

Imagine a school wants a program to calculate a student's average mark. The student has a name, class, favourite colour, five marks and a house.

Which information is essential?
Student name · class · favourite colour · five marks · house
Answer: The five marks are essential to the calculation. The name may be useful for identifying the result, but favourite colour and house are irrelevant to the calculation. Abstraction means concentrating on the important features and ignoring unnecessary detail.
36–44 min · Design

5 · Three ways to design the solution

MethodWhat it helps us do
Structure diagramShows how a large problem is divided into modules/sub-problems.
FlowchartShows the sequence and decisions in an algorithm visually.
PseudocodeDescribes the algorithm in a structured, language-independent form.
Important: Design comes before coding. A good design reduces mistakes later.
44–50 min · Guided workout

6 · Workout: cinema ticket calculator

Problem: A cinema program asks for the number of adult tickets and child tickets. Adult tickets cost $10 and child tickets cost $6. The program calculates and displays the total cost.
  1. Identify the inputs.
  2. Identify the processes.
  3. Identify the output.
  4. Write one sentence describing the purpose of the algorithm.
  5. Break the problem into smaller steps.
Inputs: number of adult tickets, number of child tickets.
Process: adult tickets × 10 + child tickets × 6.
Output: total cost.
Purpose: calculate and display the total cinema ticket cost.
Steps: input adult tickets → input child tickets → calculate adult cost → calculate child cost → add costs → output total.
Teacher challenge

7 · One problem, many solutions

Ask students to design the same cinema problem as:

  • a structure diagram
  • a flowchart
  • pseudocode
The purpose is not to make three different algorithms. The underlying solution should remain logically equivalent while the representation changes.

11 · Mini challenge — Parking fee

Problem: A car park charges $2 for the first hour and $1.50 for every additional hour. Input the number of hours and calculate the total fee.

Before seeing the answer, identify:

  1. Inputs
  2. Processes
  3. Outputs
  4. One decision/condition that the algorithm may need
Input: number of hours. Process: if hours = 1, fee = 2; otherwise fee = 2 + (hours − 1) × 1.50. Output: total fee. Condition: whether the number of hours is 1 or more than 1.

12 · Design challenge

Problem: A sports club wants a program that inputs the number of adult members and child members and calculates the total membership fee. Adult membership = $50; child membership = $30.

Your task: Write the IPO analysis and list the steps of the solution in plain English.

Input: adult members, child members. Process: adult members × 50 + child members × 30. Output: total membership fee. Steps: input adult members → input child members → calculate adult fee → calculate child fee → add fees → output total.

13 · Exit challenge

A school cafeteria program inputs the number of meals sold and the price per meal. It calculates and displays total sales.

Can you identify the IPO without looking?

Input: number of meals, price per meal. Process: number of meals × price per meal. Output: total sales.
