Functions, Procedures and Modular Solutions

Students now move from writing one long algorithm to creating small, reusable modules. The period distinguishes procedures from functions and focuses on parameters, return values, local processing and meaningful decomposition.

Core idea: A good subroutine performs one clear job. A function returns a value; a procedure performs an action without needing to return a value.

1 · Why use subroutines?

A program needs to validate a mark in three different places. Should the validation algorithm be written three times?
No. A reusable function or procedure can perform the task consistently and reduce duplication.
8–18 min · Teach

2 · Procedure basics

PROCEDURE DisplayMessage(Message)
  OUTPUT Message
ENDPROCEDURE

CALL DisplayMessage("Welcome")

The procedure receives a parameter and performs an action. It does not need to return a value.

18–27 min · Teach

3 · Function basics

FUNCTION Square(Number)
  RETURN Number * Number
ENDFUNCTION

Result ← Square(7)
OUTPUT Result

The function calculates and returns a value that can be stored, compared or used in another expression.

27–35 min · Worked example

4 · Example #1 — Validation function

FUNCTION ValidMark(Mark)
  IF Mark >= 0 AND Mark <= 100 THEN
    RETURN TRUE
  ELSE
    RETURN FALSE
  ENDIF
ENDFUNCTION
The main algorithm can now ask ValidMark(Mark) whenever it needs the same validation rule.
35–42 min · Worked example

5 · Example #2 — Average function

FUNCTION Average(A, Count)
  Total ← 0
  FOR I ← 1 TO Count
    Total ← Total + A[I]
  NEXT I
  RETURN Total ÷ Count
ENDFUNCTION

This separates the calculation from the main program. The function can be called whenever an average is required.

2 · Worked Example #1 — Maximum function

FUNCTION Maximum(A, Count)
  Highest ← A[1]
  FOR I ← 2 TO Count
    IF A[I] > Highest THEN
      Highest ← A[I]
    ENDIF
  NEXT I
  RETURN Highest
ENDFUNCTION

The main program can simply use Maximum(Marks, 10) when it needs the highest mark.

3 · Workout — Procedure with a parameter

5 · Worked Example #2 — Reusable pass check

FUNCTION HasPassed(Mark)
  RETURN Mark >= 50
ENDFUNCTION

IF HasPassed(Mark) THEN
  OUTPUT "Pass"
ELSE
  OUTPUT "Fail"
ENDIF

The function makes the rule clear and reusable.

6 · Workout — Temperature conversion

Create a function Fahrenheit(Celsius) that returns the Fahrenheit equivalent of a Celsius value.
FUNCTION Fahrenheit(Celsius)
  RETURN (Celsius × 9 ÷ 5) + 32
ENDFUNCTION

7 · Worked Example #3 — Modular mark system

FUNCTION ValidMark(Mark)
  RETURN Mark >= 0 AND Mark <= 100
ENDFUNCTION

FUNCTION IsPass(Mark)
  RETURN Mark >= 50
ENDFUNCTION

PROCEDURE DisplaySummary(Average, Passes)
  OUTPUT Average
  OUTPUT Passes
ENDPROCEDURE

A larger solution can use several focused modules rather than one very long block of code.

8 · Debugging workout

FUNCTION Double(Number)
  Number ← Number × 2
ENDFUNCTION

Result ← Double(6)
OUTPUT Result

Why is this likely to be a problem?

The function changes its local value but does not explicitly RETURN the result. A suitable version is RETURN Number × 2.

10 · Challenge — Function for the minimum

Write a function Minimum(A, Count) that returns the smallest value in an array.
FUNCTION Minimum(A, Count)
  Smallest ← A[1]
  FOR I ← 2 TO Count
    IF A[I] < Smallest THEN
      Smallest ← A[I]
    ENDIF
  NEXT I
  RETURN Smallest
ENDFUNCTION

13 · Common mistakes

  • Confusing a procedure with a function.
  • Forgetting to pass required parameters.
  • Forgetting to return a value from a function.
  • Using a function when an action-only procedure would be clearer.
  • Making one subroutine responsible for too many unrelated tasks.
  • Repeating code instead of creating a reusable module.
