Turning Analysis into an Algorithm

In Period 1 students learned to analyse a problem. Now we turn that analysis into a clear sequence of steps. The emphasis is on algorithmic thinking before students worry about programming-language syntax.

Cambridge alignment: students are expected to use design methods such as pseudocode and flowcharts to design solutions. This period concentrates on simple sequence and prepares students for selection and iteration later.
Teaching route

From IPO to algorithm

Key idea: A sequence algorithm carries out instructions in order, from first step to last, with no decision or repetition required.

0–8 min · Retrieval

1 · Rebuild yesterday's IPO

Problem: A program inputs the length and width of a rectangle and displays its area.
  1. What are the inputs?
  2. What is the process?
  3. What is the output?
Input: length, width. Process: length × width. Output: area.
8–18 min · Teach

2 · What makes an algorithm good?

ClearEach step is unambiguous.
OrderedSteps occur in the correct sequence.
FiniteThe algorithm eventually finishes.
EffectiveEach step can actually be carried out.
A solution can be mathematically correct but still be poorly designed if its steps are unclear or incomplete.
18–28 min · Worked example

3 · Example #1 — Temperature conversion

Problem: Input a temperature in Celsius and display the equivalent Fahrenheit temperature. Formula: F = (C × 9 ÷ 5) + 32.
1. INPUT Celsius
2. Fahrenheit ← (Celsius × 9 ÷ 5) + 32
3. OUTPUT Fahrenheit

Notice the sequence: input → calculate → output.

28–35 min · Workout

4 · Example #2 — Shopping total

Problem: Input the price of three items. Calculate and display the total.

Ask students to write the three algorithm steps before seeing the solution.

1. INPUT Price1
2. INPUT Price2
3. INPUT Price3
4. Total ← Price1 + Price2 + Price3
5. OUTPUT Total
35–42 min · Teaching point

5 · Assignment and calculation

An algorithm often stores a calculated result in a variable before displaying it.

Total ← Price1 + Price2 + Price3
Average ← Total ÷ 3
Read ← as “is assigned”. The value on the right is calculated and stored in the variable on the left.
42–47 min · Workout

6 · Example #3 — Salary calculation

Problem: Input basic salary and bonus. Calculate and display gross salary.

Challenge students: identify IPO, then write a 3-step algorithm.

Input: basic salary, bonus. Process: gross ← basic + bonus. Output: gross salary.

INPUT Basic
INPUT Bonus
Gross ← Basic + Bonus
OUTPUT Gross
47–50 min · Exit

7 · Teacher challenge

Ask students to describe, without code, the algorithm for calculating the perimeter of a rectangle.

Expected: input length and width → calculate perimeter = 2 × (length + width) → output perimeter.

2 · Worked Example #1 — Rectangle area

Problem: Input length and width. Calculate area. Display area.
INPUT Length
INPUT Width
Area ← Length × Width
OUTPUT Area

5 · Worked Example #2 — Shopping total

Problem: A customer buys three products. Input the three prices and display the total.
INPUT Price1
INPUT Price2
INPUT Price3
Total ← Price1 + Price2 + Price3
OUTPUT Total

If the prices are 12, 8 and 15, the total is 35.

6 · Workout — Taxi fare

Problem: A taxi charges a fixed $4 plus $2 for every kilometre. Input kilometres travelled and display the fare.

Write the IPO and pseudocode yourself.

IPO: input = kilometres; process = 4 + (kilometres × 2); output = fare.

INPUT Kilometres
Fare ← 4 + (Kilometres × 2)
OUTPUT Fare

7 · Worked Example #3 — Celsius to Fahrenheit

INPUT Celsius
Fahrenheit ← (Celsius × 9 ÷ 5) + 32
OUTPUT Fahrenheit

For Celsius = 20: Fahrenheit = 68.

8 · Workout — Convert minutes

Problem: Input a number of minutes and convert it into hours and remaining minutes. For example, 135 minutes → 2 hours 15 minutes.

Hint: Use integer division and MOD.

INPUT Minutes
Hours ← Minutes DIV 60
Remaining ← Minutes MOD 60
OUTPUT Hours
OUTPUT Remaining

For 135: Hours = 2 and Remaining = 15.

9 · Workout — Marks and average

Problem: Input four marks, calculate total and average, then display both.

Write the algorithm yourself. Check only after completing it.

INPUT M1
INPUT M2
INPUT M3
INPUT M4
Total ← M1 + M2 + M3 + M4
Average ← Total ÷ 4
OUTPUT Total
OUTPUT Average

10 · Debug the algorithm

INPUT Length
Area ← Length + Width
INPUT Width
OUTPUT Area

Find two errors.

1. Width is used before it is input. 2. Area should be Length × Width, not Length + Width.

11 · Challenge — Discount calculator

Problem: Input an item's price and discount percentage. Calculate the discount amount and final price. Display both.

Design the IPO and pseudocode.

IPO: input price, discount percentage; process discount = price × discount ÷ 100, final = price − discount; output discount and final price.

INPUT Price
INPUT DiscountPercent
Discount ← Price × DiscountPercent ÷ 100
FinalPrice ← Price − Discount
OUTPUT Discount
OUTPUT FinalPrice

12 · Mini exam question

A program inputs the number of books bought and the price of each book. Write an algorithm to calculate and display the total cost.

INPUT NumberOfBooks
INPUT Price
Total ← NumberOfBooks × Price
OUTPUT Total

13 · Common mistakes

  • Using a variable before assigning/inputting a value.
  • Putting steps in the wrong order.
  • Forgetting to output the required result.
  • Using + when the problem requires ×.
  • Writing code syntax instead of clear algorithmic steps.
