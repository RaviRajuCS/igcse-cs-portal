Testing Algorithms Systematically

Students now learn to prove that their algorithms work by using carefully chosen test data. They will trace algorithms by hand, predict outputs, identify errors and improve their tests.

Core idea: Do not ask only “Does it work?” Ask “What evidence shows that it works for normal, boundary and invalid data?”

1 · Why test?

A program gives the correct answer for 50, but nobody has tried 0, 100 or an invalid value. Can we confidently say the program is correct?
No. A stronger test set includes normal values, boundary values and invalid or exceptional values where appropriate.
8–18 min · Teach

2 · Trace a simple algorithm

Total ← 0
FOR I ← 1 TO 3
  INPUT Number
  Total ← Total + Number
NEXT I
OUTPUT Total

If the inputs are 4, 7 and 9, the expected output is 20. A trace follows the value of Total after every iteration.

5 · Example #2 — Finding a logic error

Count ← 0
FOR I ← 1 TO 5
  INPUT Mark
  IF Mark > 50 THEN
    Count ← Count + 1
  ENDIF
NEXT I

If the requirement is to count marks 50 or above, what happens to a mark of exactly 50?

It is not counted. The condition should be Mark >= 50.
42–47 min · Guided workout

6 · Design a test set

For an algorithm that accepts a positive integer from 1 to 20 inclusive, choose five strong test values.
A strong set is 0, 1, 2, 10, 20, 21. This actually gives six values: 0 and 21 test invalid boundaries, 1 and 20 test valid boundaries, and 2/10 test valid normal values.

For a mark range 0–100 inclusive, give one invalid-below, lower-boundary, normal, upper-boundary and invalid-above test value.

5 · Worked Example #2 — Search testing

Found ← FALSE
FOR I ← 1 TO 5
  IF A[I] = Target THEN
    Found ← TRUE
  ENDIF
NEXT I

For A = [4, 8, 12, 15, 20], test a target that is first, middle, last and absent.

4 (first), 12 (middle), 20 (last), 9 (absent).

6 · Debugging workout

Total ← 0
FOR I ← 1 TO 5
  INPUT Number
  Total ← Number
NEXT I
OUTPUT Total

Why does this not calculate the total?

Each new Number replaces Total. The algorithm needs Total ← Total + Number so previous values are accumulated.

8 · Worked Example #3 — Sorting test

An ascending sort should correctly handle an already sorted list, a reverse-sorted list, duplicate values and a single-value list.
Already sorted: [1,2,3,4] · Reverse: [4,3,2,1] · Duplicates: [2,4,2,1] · Single: [7]. These expose different possible problems.

9 · Workout — Find the first failure

IF Mark > 0 AND Mark < 100 THEN
  OUTPUT "Valid"
ELSE
  OUTPUT "Invalid"
ENDIF

If 0–100 inclusive is required, which two boundary values expose the error?

0 and 100. Both should be valid, but the strict inequalities reject them.

10 · Challenge — Trace and predict

X ← 2
FOR I ← 1 TO 3
  X ← X × 2
NEXT I
OUTPUT X

Predict the output before revealing it.

The values are 4, 8, 16. Expected output: 16.

11 · Think like an examiner

A program works for ordinary values but fails at 100. What kind of test data should have been included?

12 · Mini exam question

An algorithm accepts a whole number from 1 to 50 inclusive. Give a suitable set of test values and explain why each type is useful.

0 invalid below; 1 lower boundary; 25 normal; 50 upper boundary; 51 invalid above. Together these test the limits and typical valid input.

13 · Common mistakes

  • Recording only final values instead of tracing changes.
  • Testing normal values but ignoring boundaries.
  • Not writing expected results before running the test.
  • Changing the algorithm after seeing a wrong result without finding the cause.
  • Assuming one successful test proves correctness.

14 · Self-assessment

Can you trace an algorithm, choose strong test data and diagnose a logic error?
