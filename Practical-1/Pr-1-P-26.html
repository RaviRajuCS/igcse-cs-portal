Menu-Driven Programs and Interactive Solutions

Students now combine selection, repetition, validation and subroutines to build practical menu-driven programs. The emphasis is on keeping the menu active until the user chooses to exit, while ensuring every choice is valid and each operation is handled cleanly.

Core idea: A menu-driven program repeatedly presents choices, validates the user's selection, performs the selected operation and returns to the menu until an exit option is chosen.

1 · What makes a menu-driven program?

A program offers Add, Search, Display and Exit. After Add finishes, should the program immediately end?
Normally no. It should return to the menu so the user can choose another operation, unless the selected operation is Exit.
8–18 min · Teach

2 · Basic menu structure

Choice ← 0
WHILE Choice <> 4 DO
  OUTPUT "1. Add"
  OUTPUT "2. Search"
  OUTPUT "3. Display"
  OUTPUT "4. Exit"
  INPUT Choice
  IF Choice = 1 THEN
    OUTPUT "Add selected"
  ELSE
    IF Choice = 2 THEN
      OUTPUT "Search selected"
    ELSE
      IF Choice = 3 THEN
        OUTPUT "Display selected"
      ENDIF
    ENDIF
    ENDIF
ENDWHILE
18–27 min · Teach

3 · Why validate the menu choice?

INPUT Choice
WHILE Choice < 1 OR Choice > 4 DO
  OUTPUT "Choose 1 to 4"
  INPUT Choice
ENDWHILE

Validation keeps unexpected choices away from the selection logic. The exit value is part of the valid menu range.

27–35 min · Worked example

4 · Example #1 — Menu with subroutines

PROCEDURE AddRecord()
  OUTPUT "Add record"
ENDPROCEDURE

PROCEDURE SearchRecords()
  OUTPUT "Search records"
ENDPROCEDURE

Choice ← 0
WHILE Choice <> 3 DO
  OUTPUT "1 Add 2 Search 3 Exit"
  INPUT Choice
  IF Choice = 1 THEN
    CALL AddRecord()
  ELSE
    IF Choice = 2 THEN
      CALL SearchRecords()
    ENDIF
    ENDIF
ENDWHILE
The main loop controls the menu; each operation is delegated to a focused procedure.

Create a four-option menu for a simple student record system: Add, Search, Display and Exit. State which option should terminate the loop.

7 · Worked Example #3 — Menu + procedure

PROCEDURE DisplayAverage(A, Count)
  OUTPUT Average(A, Count)
ENDPROCEDURE

Choice ← 0
WHILE Choice <> 2 DO
  OUTPUT "1 Display average"
  OUTPUT "2 Exit"
  INPUT Choice
  IF Choice = 1 THEN
    CALL DisplayAverage(Marks, 8)

ENDWHILE

The menu controls the interaction while the procedure owns the operation.

8 · Debugging workout

Choice ← 0
WHILE Choice <> 4 DO
  OUTPUT "1 Add"
  OUTPUT "2 Search"
  OUTPUT "3 Display"
  OUTPUT "4 Exit"
  INPUT Choice
  IF Choice = 1 THEN
    OUTPUT "Add"
  ENDIF
ENDWHILE

What happens when the user chooses 2 or 3?

Nothing happens for choices 2 and 3 because there are no corresponding branches. The program needs selection branches for every valid operation.

13 · Common mistakes

  • Forgetting the loop around the menu.
  • Not validating choices outside the menu range.
  • Forgetting to implement one of the valid options.
  • Accidentally placing Exit inside an operation branch.
  • Failing to return to the menu after an operation.
  • Repeating large blocks of code instead of using procedures.
