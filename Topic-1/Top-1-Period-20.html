My teaching route
Lesson overview

Period 20 · Topic 1 Consolidation

Purpose: Bring together the major ideas covered so far in Data Representation and prepare students for a formal Topic 1 assessment.

Success criteria: Students can move between number representation, character representation, sound representation, image representation, storage calculations and compression without confusing the key terms or formulas.

Prior learning: Periods 1–19 of Topic 1.

Teacher focus: Diagnose misconceptions, strengthen exam technique, and identify students who need targeted reteaching.

My teaching route

The Topic 1 map

  1. Number systems: denary, binary, hexadecimal and conversions.
  2. Text: character sets, ASCII and Unicode.
  3. Sound: sampling, sample rate and sample resolution.
  4. Images: pixels, resolution and colour depth.
  5. Storage: bits, bytes and storage units.
  6. Compression: lossy, lossless and RLE.
Teaching principle: students should explain relationships, not merely recall isolated definitions.

5–12 min · Number systems

Conversion checkpoint

Use these as quick board questions:

  • Convert 45₁₀ to binary.
  • Convert 101101₂ to denary.
  • Convert 2F₁₆ to denary.
  • Convert 58₁₀ to hexadecimal.
Teacher check: ask students to show working. A correct answer without a reliable method is not enough for a consolidation lesson.
12–19 min · Text

ASCII and Unicode checkpoint

  1. How many bits does standard ASCII use?
  2. How many codes does 7-bit ASCII provide?
  3. What is ASCII 65?
  4. Why is Unicode needed?
Common misconception: Unicode is not “just another binary system”. It is a much larger character set.
19–27 min · Sound

Sound checkpoint

TermMeaning
SamplingTaking measurements of an analogue sound signal at regular intervals
Sample rateNumber of samples taken per second
Sample resolutionNumber of bits used for each sample

Calculation: sample rate × sample resolution × duration = raw file size in bits.

27–34 min · Images

Image checkpoint

TermMeaning
PixelA picture element in a bitmap image
ResolutionNumber of pixels, commonly width × height
Colour depthBits used to represent colour information

Calculation: width × height × colour depth = raw image size in bits.

34–40 min · Compression

Compression checkpoint

  • Compression: reduces file size.
  • Lossy: permanently removes some data.
  • Lossless: reduces size without permanent loss of data.
  • RLE: represents consecutive repeated values using run information.
Exam trap: RLE does not count all occurrences of a value. It counts consecutive runs.
40–47 min · Mixed assessment

Mini Topic 1 Test

  1. Convert 37₁₀ to binary.
  2. State the number of bits in a standard ASCII code.
  3. Explain why Unicode is needed.
  4. Define sample rate.
  5. An image is 500 × 400 pixels with 8-bit colour depth. Calculate its size in bytes.
  6. Explain one reason for compressing a file.
  7. Encode AAAAABBBCC using RLE.
Teacher strategy: let students work independently first, then review each answer by discussing the method rather than simply displaying the answer.
47–50 min · Exit ticket

Readiness check

  1. Which Topic 1 area are you strongest in?
  2. Which area needs another explanation?
  3. Can you calculate both sound and image file sizes?

4 · Image

An image is 500 × 400 pixels with 8-bit colour depth. Calculate the size in bytes.

Pixels = 500 × 400 = 200,000.
Bits = 200,000 × 8 = 1,600,000 bits.
Bytes = 1,600,000 ÷ 8 = 200,000 bytes.

8 · Exam technique

  • Read the unit requested before calculating.
  • Show working for multi-step calculations.
  • Use the exact terminology from the question.
  • For “explain” questions, give a reason and its consequence.
  • For RLE, identify consecutive runs.
