LESSON 12

Data Storage & File Size

Understand how digital data occupies storage space, convert between storage units, calculate capacity, and solve realistic storage-planning problems.

🎯 Learning Objectives

By the end of this lesson, you should be able to:

  • Explain the relationship between bits, bytes and larger storage units.
  • Convert correctly between bits, bytes, KiB, MiB and GiB.
  • Calculate the storage occupied by collections of files.
  • Calculate remaining storage capacity.
  • Determine how many files can fit into available storage.
  • Distinguish between file size and storage capacity.
  • Apply a clear exam method to multi-step storage calculations.
  • Recognise common unit-conversion errors.

🔁 What We Already Know

Bit

The smallest unit of binary data.

0 or 1

Byte

Eight bits make one byte.

1 byte = 8 bits

KiB

Used for binary storage calculations.

1 KiB = 1024 bytes

MiB

A larger binary storage unit.

1 MiB = 1024 KiB

GiB

A still larger binary storage unit.

1 GiB = 1024 MiB
bits ÷ 8 bytes ÷ 1024 KiB ÷ 1024 MiB ÷ 1024 GiB
Remember: Moving from a smaller unit to a larger unit means dividing. Moving from a larger unit to a smaller unit means multiplying.

📦 Storage Units — The Complete Picture

Unit Relationship Direction
Byte 8 bits bits → bytes: ÷8
KiB 1024 bytes bytes → KiB: ÷1024
MiB 1024 KiB KiB → MiB: ÷1024
GiB 1024 MiB MiB → GiB: ÷1024

Exam rule: If the question uses 1024, continue using 1024 throughout the calculation unless the question explicitly tells you otherwise.

🧠 Why Does File Size Matter?

Every digital file occupies space in a storage device. A computer may contain thousands of images, sound files, documents and videos. Understanding file size allows us to determine whether those files will fit within the available storage.

The important idea is that file size and storage capacity are not the same thing.

File Size

How much storage one particular file requires.

Storage Capacity

How much data a storage device can hold.

✏️ Worked Example 1 — Bits to MiB

Question: Convert 5,000,000 bits into bytes, KiB and MiB.

Step 1 — bits → bytes

5,000,000 ÷ 8 = 625,000 bytes

Step 2 — bytes → KiB

625,000 ÷ 1024 = 610.3515625 KiB

Step 3 — KiB → MiB

610.3515625 ÷ 1024 ≈ 0.596 MiB
Answer: approximately 0.596 MiB

✏️ Worked Example 2 — MiB to Bits

Question: Convert 3.5 MiB into bytes and bits.

Step 1 — MiB → KiB

3.5 × 1024 = 3584 KiB

Step 2 — KiB → bytes

3584 × 1024 = 3,670,016 bytes

Step 3 — bytes → bits

3,670,016 × 8 = 29,360,128 bits
Answer: 3.5 MiB = 3,670,016 bytes = 29,360,128 bits

✏️ Worked Example 3 — GiB All the Way Down

Question: Convert 2 GiB into MiB, KiB, bytes and bits.

2 GiB × 1024 = 2048 MiB 2048 MiB × 1024 = 2,097,152 KiB 2,097,152 KiB × 1024 = 2,147,483,648 bytes 2,147,483,648 × 8 = 17,179,869,184 bits
Final: 2 GiB = 2048 MiB = 2,097,152 KiB = 2,147,483,648 bytes = 17,179,869,184 bits

📚 Storage Planning

Real storage problems often involve more than one file. We must first calculate the total amount already used and then determine how much space remains.

Example

A storage device has a capacity of 2 GiB. 500 MiB is already being used. Each new file requires 120 MiB. How many complete files can be stored?

Convert the capacity:

2 GiB = 2 × 1024 = 2048 MiB

Find remaining storage:

2048 − 500 = 1548 MiB

Find the number of complete files:

1548 ÷ 120 = 12.9

We cannot store 0.9 of a file, so we take the whole-number part.

Maximum files = 12

Space remaining after 12 files:

1548 − (12 × 120) = 108 MiB

🧩 Mixed File Collections

Sometimes we need to calculate the total size of several different types of files.

File Type Number Size Each Total
Images 8 18 MiB 144 MiB
Audio 5 25 MiB 125 MiB
Video 2 180 MiB 360 MiB
Total storage required = 144 + 125 + 360 = 629 MiB

⚠️ Important Distinction: Calculated vs Actual File Size

In earlier lessons, we calculated raw bitmap and sound sizes from their representation parameters. Those calculations describe the amount of data before compression and additional file-format considerations.

The actual size of a stored file can be different because file formats, metadata and compression may affect the amount of storage required.

For Cambridge calculations: use the information and formula given in the question. Do not invent compression or metadata adjustments unless the question asks for them.

🔍 Fix the Mistake

Mistake 1: A student converts 8000 bits to bytes by multiplying by 8.

Wrong direction. Bits → bytes means divide by 8. 8000 ÷ 8 = 1000 bytes.

Mistake 2: A student converts 4 MiB to KiB by dividing by 1024.

Wrong direction. MiB → KiB means multiply. 4 × 1024 = 4096 KiB.

Mistake 3: A student says 2 GiB contains 2000 MiB.

In this Cambridge-style binary calculation, 2 GiB = 2 × 1024 = 2048 MiB.

Mistake 4: A student divides available space by file size and writes 12.9 files.

You cannot store a fraction of a complete file. The maximum is 12 complete files.

📝 Exam Method

  1. Identify the units. Write them beside every number.
  2. Choose one common unit. MiB is often convenient.
  3. Convert before calculating.
  4. Calculate the total used storage.
  5. Subtract from capacity when finding remaining space.
  6. Divide available space by file size when finding how many files fit.
  7. Use the whole-number part when complete files are required.
  8. Check your units and answer.

🏆 Challenge

A storage device has a capacity of 4 GiB. It already contains 1.25 GiB of data. New files require 90 MiB each.

Questions:

  1. How much space remains in MiB?
  2. What is the maximum number of complete files that can be added?
  3. How much space remains afterwards?

4 GiB = 4096 MiB

1.25 GiB = 1280 MiB

Remaining = 4096 − 1280 = 2816 MiB

2816 ÷ 90 = 31.28...

Maximum complete files = 31

31 × 90 = 2790 MiB

Final remaining space = 26 MiB

🚨 Common Mistakes

  • Confusing bits with bytes.
  • Multiplying when the conversion requires division.
  • Dividing when the conversion requires multiplication.
  • Mixing MiB and GiB in the same calculation.
  • Using 1000 when the question expects 1024.
  • Forgetting storage already in use.
  • Adding file sizes without first converting them to the same unit.
  • Giving a fractional answer when complete files are required.
