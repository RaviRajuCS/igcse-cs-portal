My teaching route
Lesson overview

Period 18 · Run Length Encoding (RLE)

Cambridge focus: Run Length Encoding (RLE) is specified as an example of lossless compression. Students need to understand how files are compressed using lossless methods.

Success criteria: Students can explain RLE, identify repeated runs of data, encode runs using a count and value, decode an RLE sequence, and explain when RLE is effective or ineffective.

Prior learning: Period 17 — compression, lossy and lossless methods.

Key vocabulary: RLE, run, repeated data, count, value, encode, decode, flag, lossless, compression ratio.

My teaching route

Teach RLE visually

  1. Write a repeated sequence on the board.
  2. Circle each consecutive run.
  3. Replace each run with count + value.
  4. Compare original length with encoded length.
  5. Decode the result to prove that no information has been permanently lost.
Core idea: RLE stores repeated units as a count followed by the value being repeated.
0–5 min · Retrieval

Reconnect with compression

  1. What is compression?
  2. What is the difference between lossy and lossless compression?
  3. Which type allows the original data to be restored exactly?
Bridge: Today we will learn one specific lossless technique: RLE.
5–13 min · Discover

Find the runs

Consider:

AAAAABBBBCCDDDDD

Do not read this as 16 separate characters. Group consecutive identical characters:

AAAAA | BBBB | CC | DDDDD

These are four runs.

13–22 min · Model

Encode the runs

Replace each run with its count and value:

5A | 4B | 2C | 5D

The original sequence has 16 characters. The compressed representation has 8 values if each count and character occupies one unit.

16 units → 8 units = 50% of the original size.

This is why RLE works particularly well when there are long runs of repeated values.

30–35 min · Decode

Reverse the process

RLE must be reversible. Decode:

3A | 2B | 4C

Students expand each pair:

AAA | BB | CCCC → AAABBCCCC

Because the original sequence can be reconstructed, this is lossless compression.

35–40 min · When does RLE work?

Effective vs ineffective data

DataRLE result
AAAAAAAABBBBBBBBVery effective
11111111110000000000Very effective
ABABABABABNot effective
CDCDCDCDCDNot effective
Rule: RLE benefits from consecutive repetition. Alternating data produces many short runs.
40–44 min · Flag concept

Why can a flag be useful?

When data contains many runs of one character, RLE is straightforward. But a sequence with many single items can be awkward because the count itself adds data.

The textbook introduces a flag to distinguish encoded run information from ordinary data. For example, a flag can precede a count and value when a run is being encoded.

Teacher message: the flag removes ambiguity about how the following values should be interpreted.
44–48 min · Assessment

Cambridge-style RLE questions

  1. What is meant by RLE?
  2. Encode AAAAABBCCCCC using count + value pairs.
  3. Decode 4A 3B 2C.
  4. Explain why RLE is a lossless compression method.
  5. Suggest why RLE may be ineffective for ABABABAB.
Marking focus: students should identify consecutive runs, not simply count how many times a character appears anywhere in the string.
48–50 min · Exit ticket

Three questions before you leave

  1. What does RLE store instead of every repeated item?
  2. Why is RLE lossless?
  3. Give one type of data where RLE is likely to work well.
Teacher decision: Period 19 can extend RLE to bitmap-style data and examine compression effectiveness and flags in more detail.

8 · Why can RLE fail?

Consider:

CDCDCDCDCD

There are many runs of length 1. Storing a count for every single character can add overhead instead of saving space.

Key idea: RLE is not automatically effective for every file.

9 · Exam practice

Question: Explain why RLE is a lossless compression method.

RLE represents consecutive repeated data using a count and the value. The original sequence can be reconstructed exactly from these count-and-value pairs, so no data is permanently lost.

10 · Common mistakes

  • Counting all occurrences instead of consecutive occurrences.
  • Forgetting to include the value after the count.
  • Thinking RLE always makes a file smaller.
  • Calling RLE lossy because the stored representation looks different.
  • Forgetting that the encoded data must be decodable back to the original.
