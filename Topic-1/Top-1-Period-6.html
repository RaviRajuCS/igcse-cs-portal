Lesson overview

Period 6 · Overflow in Binary Addition

Cambridge focus: Topic 1.1 Number systems. Students need to understand overflow as a consequence of exceeding the capacity of the available number of bits. The syllabus also expects understanding of the effect of the number of bits available on the range of values that can be represented. fileciteturn7file0L14-L18

Success criteria: Students can identify when binary addition produces overflow, explain why it occurs, calculate the maximum value representable with a given number of bits, and distinguish an ordinary carry from an overflow error.

Prior learning: Period 5 — binary addition and carrying.

Key vocabulary: overflow, carry, register, bit, range, maximum value, 8-bit, 16-bit, represent, error.

Teacher preparation

Before students enter

  • Review the 8-bit range: 0–255 for positive unsigned binary integers.
  • Prepare one addition that stays within 8 bits and one that produces a ninth bit.
  • Keep the distinction visible: carry = part of addition; overflow = result cannot fit in the available bits.
  • Prepare a quick comparison of 8-bit, 16-bit and 32-bit maximum values.
Teaching principle: students should discover overflow by comparing the mathematical result with the storage capacity, not by treating “a ninth bit” as a definition without explanation.
0–5 min · Retrieval

Reconnect with binary addition

  1. What is 1 + 1 in binary?
  2. Why do we carry when a column contains 1 + 1?
  3. Add 01010100₂ + 00001011₂.
  4. What is the largest positive value that can be represented using 8 unsigned bits?
Bridge: The arithmetic can be correct while the stored answer is wrong if there are not enough bits to hold the result.
5–14 min · Discover

What does “8-bit” limit?

An 8-bit positive binary number has place values 128, 64, 32, 16, 8, 4, 2 and 1.

The largest value is:

128 + 64 + 32 + 16 + 8 + 4 + 2 + 1 = 255

Therefore an 8-bit unsigned representation can store values from 0 to 255. The textbook gives the same maximum as 2⁸ − 1. fileciteturn6file2L147-L158

14–24 min · Model

Example of overflow

Use the textbook-style example:

  01101110   (110)
+ 11011110   (222)
-----------
1 01001100

The mathematical result is 332, but only eight result bits are available.

If the ninth bit is discarded, the stored 8-bit result is 01001100₂ = 76₁₀, which is incorrect.

Conclusion: the ninth bit shows that the result exceeded the maximum value that can be represented using 8 bits. This is overflow. fileciteturn6file2L147-L154
24–32 min · Explain

Carry versus overflow

Carry: a value is carried from one binary column to the next during normal addition.

Overflow: the final mathematical result is outside the range that can be represented using the available number of bits.

Example: 200 + 30 = 230 fits in 8 bits → no overflow. 200 + 70 = 270 does not fit in 8 bits → overflow.

Ask: Can an addition contain carries without producing overflow? Yes. Can the final carry indicate overflow in an unsigned fixed-width addition? Yes.

32–38 min · Explore

More bits = larger range

For unsigned binary integers, the maximum value is 2ⁿ − 1, where n is the number of bits.

  • 8 bits → 2⁸ − 1 = 255
  • 16 bits → 2¹⁶ − 1 = 65,535
  • 32 bits → 2³² − 1 = 4,294,967,295

The textbook explicitly uses these examples to show how increasing the number of bits increases the range of values that can be stored. fileciteturn6file2L155-L158

38–44 min · Differentiation

Three levels of challenge

Support: Decide whether 120 + 100, 100 + 50 and 200 + 40 overflow an 8-bit unsigned register.

Core: Convert each pair to 8-bit binary, add them and identify overflow.

Challenge: Explain why the same mathematical calculation might fit in a 16-bit register but overflow an 8-bit register.

44–47 min · Assessment

Mini-whiteboard check

  1. What is the maximum unsigned value in 8 bits?
  2. Does 180 + 50 produce overflow in 8 bits?
  3. Why does a ninth bit indicate a problem in an 8-bit result?
Look for: students who call every carry “overflow”. Ask them to compare the final mathematical result with 255.
47–50 min · Exit ticket

Three questions before you leave

  1. State the maximum unsigned value represented by 8 bits.
  2. Does 200 + 55 cause overflow in 8 bits? Explain.
  3. In one sentence, distinguish a carry from overflow.
Teacher decision: If students can identify and explain overflow, Period 7 can move to logical binary shifts. If not, use a short 8-bit range recap first.

Today you will learn what happens when a binary result is too large to fit into the number of bits available.

🎯 Learning goals

  • Explain what overflow means.
  • Identify overflow in an 8-bit unsigned binary addition.
  • Calculate the maximum value that can be represented with a given number of bits.
  • Distinguish a normal carry from an overflow error.
  • Explain why more bits allow a larger range of values.

1 · The 8-bit limit

An unsigned 8-bit number has these place values:

128
64
32
16
8
4
2
1

The largest possible value uses 1 in every position:

11111111
128 + 64 + 32 + 16 + 8 + 4 + 2 + 1 = 255

So the range is 0 to 255.

2 · What is overflow?

Overflow occurs when the mathematical result is too large to be represented using the available number of bits.

For example:

  01101110
+ 11011110
-----------
1 01001100

The true answer is 332. But 332 is greater than 255, so it cannot be stored in an 8-bit unsigned representation.

Overflow has occurred.

3 · Why is the stored answer wrong?

If the ninth bit is discarded, the stored eight bits are:

01001100

That represents 76₁₀, not 332₁₀.

The problem is not the addition. The problem is that the available 8-bit representation cannot hold the mathematical result.

4 · Carry or overflow?

A carry happens during the normal addition process.

Overflow happens when the final value is outside the representable range.

200 + 30 = 230 → fits in 8 bits → no overflow.

200 + 70 = 270 → greater than 255 → overflow.

5 · Quick check

Q1: What is the maximum unsigned value in 8 bits?

Q2: Does 200 + 70 cause 8-bit unsigned overflow?

6 · Practice — spot the overflow

Decide whether each calculation overflows an 8-bit unsigned representation:

  1. 120 + 100
  2. 100 + 50
  3. 200 + 40
  4. 180 + 90
  5. 127 + 128
Answers:
1. Overflow (220 actually fits — so no overflow).
2. No overflow (150).
3. No overflow (240).
4. Overflow (270).
5. No overflow (255).

7 · Practice — binary

Add the following as 8-bit binary numbers and decide whether overflow occurs:

  1. 10100000 + 00110000
  2. 11001000 + 00101000
  3. 10010110 + 01101010
Answers:
1. 11010000 — no overflow (208).
2. 11110000 — no overflow (240).
3. 1 00000000 — overflow; mathematical result is 256.

8 · More bits, bigger range

  • 8 bits → maximum 255
  • 16 bits → maximum 65,535
  • 32 bits → maximum 4,294,967,295

The general rule for an unsigned n-bit number is:

Maximum value = 2ⁿ − 1

9 · Exam practice

Question: Explain why adding 200₁₀ and 70₁₀ using 8-bit unsigned binary causes overflow.

200 + 70 = 270. An 8-bit unsigned number can represent only 0–255. Since 270 is greater than 255, the result cannot be represented in 8 bits, so overflow occurs.

10 · Common mistakes

  • Calling every carry an overflow.
  • Forgetting that an 8-bit unsigned value has a maximum of 255.
  • Looking only at the binary pattern without checking the mathematical result.
  • Thinking that overflow means the computer's arithmetic operation was necessarily performed incorrectly.
  • Forgetting that increasing the number of bits increases the range of representable values.
