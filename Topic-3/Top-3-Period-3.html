Lesson overview

Period 3 · CPU Performance

This lesson builds on the CPU architecture studied in Periods 1–2. Students now investigate three factors that can affect CPU performance: number of cores, cache size and clock speed.

Success criteria: Students can define a CPU core, cache and clock speed, and explain how increasing the number of cores, cache size or clock speed can affect performance.

Cambridge specifically requires students to understand cores, cache and clock in a CPU and explain how they can affect CPU performance. citeturn0search12

My teaching route

Do not reduce performance to “GHz = faster”

  1. Retrieve the CPU's role and FDE cycle.
  2. Introduce a core as a processing unit within a CPU.
  3. Explain how multiple cores can allow more instructions/tasks to be processed at the same time.
  4. Introduce cache as fast memory close to/within the CPU.
  5. Explain how a larger cache can reduce the need to access slower main memory.
  6. Introduce clock speed as the number of clock cycles per second.
  7. Explain why clock speed is useful but not the only factor determining performance.

7–17 min · Teach

1 · CPU cores

A core is an individual processing unit within a CPU. A CPU can contain one or more cores.

1Single-core
2Dual-core
4+Multi-core

Multiple cores can allow a CPU to work on more than one instruction stream/task at the same time, particularly when software and the operating system can use the available cores effectively.

Exam wording: More cores can increase performance because more processing can be carried out concurrently.
17–27 min · Teach

2 · CPU cache

Cache is very fast memory used to store frequently or recently needed instructions and data so the CPU can access them quickly.

CPU
↔
CACHE
very fast
↔
RAM
slower

A larger cache can store more frequently used data/instructions close to the CPU. This can reduce the number of slower accesses to RAM and improve performance.

Key idea: Cache does not replace RAM. It helps the CPU obtain frequently needed information faster.
27–36 min · Teach

3 · Clock speed

The CPU clock provides regular timing signals for CPU operations. Clock speed is the number of clock cycles per second and is commonly measured in hertz (Hz), such as GHz.

1 GHz
=
1 billion
cycles/second

A higher clock speed can allow a CPU to perform more cycles per second, which can increase performance when other factors are comparable.

Important: A higher clock speed does not automatically mean every CPU is faster. Architecture, number of cores, cache and the workload also matter.

43–47 min · Application

CPU A vs CPU B

CPU A: 2 cores, 2.8 GHz, smaller cache
CPU B: 4 cores, 2.6 GHz, larger cache

Which CPU is automatically faster?

Answer: You cannot decide from clock speed alone. CPU B has more cores and a larger cache, while CPU A has the higher clock speed. The actual workload and CPU architecture also affect the result.

8 · Exam practice

Question: Explain how increasing the number of cores can affect CPU performance.

More cores provide more processing units, allowing more instructions/tasks to be processed concurrently, so performance can increase when software can use the additional cores.

Question: Explain how increasing cache size can affect CPU performance.

A larger cache can store more frequently/recently needed data and instructions close to the CPU, reducing slower accesses to RAM and potentially improving performance.

Question: Explain how clock speed can affect performance.

A higher clock speed means more clock cycles per second, so the CPU can potentially perform more processing cycles in a given time, when other factors are comparable.

9 · Challenge

A student says: “CPU X runs at 4.0 GHz, while CPU Y runs at 3.5 GHz, so CPU X must always be faster.”

The statement is too simplistic. Clock speed is one performance factor. The number of cores, cache size, CPU architecture and the workload can also affect performance. CPU X may be faster for some tasks, but the clock speed alone does not prove it will always be faster.

10 · Common exam mistakes

  • Writing that more cores always make a CPU exactly proportionally faster.
  • Calling cache “secondary storage”.
  • Confusing clock speed with the number of instructions completed per second.
  • Assuming the CPU with the highest GHz must always be fastest.
  • Forgetting to explain why a factor improves performance.
